Architecture decision record

Keep the advisor tooling in this repo

The shoulder-advisor port stays beside the blog it reviews. What that costs, how the cost is kept small, and what would reopen the question.

We will keep the advisor tooling (the post ingesters, the advisor CLI, the corpus layout and the leak check) in this repo, because the owner chose to consolidate it here when the port began, and moving it would save about 18 MB of install and no CI job while adding a second repo.

The cost is bounded by five conditions below, and seven triggers reopen the question.

Context

A shoulder advisor answers a question in the voice of one writer, grounded in that writer's posts on disk, and can review a draft against them. The tooling for it is being ported from a private Python repo to TypeScript here. Issue #110 states the goal of that port: when it is done, "consulting the advisor and reviewing prose against him need no Python and no second repo". The post sync (#109) and the foundations (#111) have landed on that basis. Issue #117 ports the consulting skill next.

The repo review in #122 (proposal 21) asked whether that was right: the tooling serves a different product from the blog, and it is the reason for the leak check and for most of the dependencies. Issue #169 asks for the answer to be recorded. This page is it. It is unlisted because it is housekeeping for the repo, not a post for readers.

  • Dependencies. cheerio, turndown and @types/turndown exist only for the ingesters, and they bring the 26 packages. yaml is shared: tests/workflows.test.mts and tests/skill-evals.test.mts parse the CI workflows with it, so it stays whatever happens to the advisor.
  • Test time. The five files take about 38 s run one after another (the pre-push hook test 23 s, the guards 12 s). npm test runs files in parallel, so on an 18-core machine they add about 1 s to its wall time (44.6 s against 43.4 s). CI's test step takes 84 s on fewer cores; the advisor's share there was not measured.
  • Documentation. The 174-line corpus/README.md holds the rules and commands. No session loads it unless it reads it.

Options considered

Keep it here

  • Follows the owner's choice in #110, with two merged PRs built on it
  • The review pipeline reads this blog's pages (docs/*.html) directly
  • One set of conventions: TypeScript 7, no build step, one test runner
  • Every install carries 26 extra packages
  • About a third of scripts/ serves a second product

Move it to its own repo

  • The blog installs 6 packages, not 32
  • Five fewer test files
  • Two repos, two CI setups and two sets of conventions to maintain
  • Reviewing a draft reaches across repos for the page
  • Reverses an explicit decision, and the leak check stays here anyway
If the advisor tooling moved out tomorrow, could this repo drop its leak check?

No. A published page here, docs/voice-notes-on-trial.html, quotes the writer on purpose, under a capped entry in LEAK_ALLOWED (scripts/advisor/guards.mts). While posts here quote a writer whose text is private, something has to check that no more of it is pushed than was reviewed. Moving the tooling would move the check's code, not the need for it.

Costs we accept

  • The install and the test files in the table above, in every checkout and in CI's check and a11y jobs.
  • Growth. #110 still has about 5,200 lines of Python to port, a 587-line Claude Code mod and about 3,100 lines of tests. Its later phases add @anthropic-ai/sdk, and @huggingface/transformers, which came to 535 MB of node_modules in the Phase 0 spike, 290 MB of it onnxruntime-node.
  • Agents working on the blog see advisor files in searches and in the tree, and the pre-push hook needs the private data linked in each worktree to do its job.

Conditions of keeping it

These bound the costs. Most are already rules, enforced by a test where one can be written.

  1. Advisor packages stay devDependencies, imported only by scripts/advisor*, scripts/ingest/ and scripts/sync-posts.mts. A heavy one goes in optionalDependencies and CI installs with --omit=optional, as #110 D5 plans. For the embedder that means @huggingface/transformers itself is optional, since it lists onnxruntime-node as an ordinary dependency.
  2. The blog's own path never imports advisor code. scripts/bh.mts reaches no advisor module and no installed package; tests/advisor-guards.test.mts pins that, because the deploy job runs with no install.
  3. No CI job, no secret and no model call for the advisor. That is in #110's acceptance criteria.
  4. Its documentation lives in corpus/README.md. CLAUDE.md keeps the pre-push paragraph and at most a one-line pointer.
  5. It keeps to its own paths: the scripts above, corpus/, tests/advisor-*, tests/sync-posts*, tests/githooks* and tests/fixtures/advisor/. Then a later move is a history split by path, not an untangling.

When to revisit

Any one of these reopens the decision. The answer then goes in a new ADR that supersedes this one.

  1. node_modules after CI's npm ci grows past 100 MB, or onnxruntime-node or model weights reach any CI job: the D5 gating has not held.
  2. The blog's path (scripts/bh.mts, scripts/publish.mts, the deploy job) has to import advisor code or an advisor package, or the guard test above has to be loosened.
  3. The advisor needs a CI job, a secret or a model call in CI.
  4. The advisor's test files take more than half of the wall time of CI's test step.
  5. A second consumer appears: another repo, or advice on writing that is not this blog's pages.
  6. No page here quotes a corpus writer and none is planned. The leak check's reason for living here then goes, and a move gets cheap.
  7. The answer to #110's open question 1 ties the code's versions to the private data repo, so that code and data have to change in lockstep.

Consequences

What gets easier

  • #110 and #117 carry on here as planned, with no decision left to wait on
  • Once #110 reaches its Phase 8, reviewing a draft is one command on the page in the same checkout
  • One type-checker, one test runner and one tsconfig.json serve both

What gets harder

  • The blog's install stays half as big again as it needs to be (55 MB against 37 MB)
  • Each advisor PR has to keep the five conditions, and a reviewer has to check them
